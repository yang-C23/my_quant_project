# 共同工作流程

本流程对所有agent相同；用户已批准的任务范围优先于历史角色约定。

任务状态为 `backlog → ready → in_progress → review → done`，发现问题可进入
`changes_requested`。阶段缺少外部数据或真实观察时间时标明 `blocked_external`，
不要将整个计划标为完成。`docs/tasks/STATUS.md`是唯一状态源。

- 任务卡写明目标、范围、证据、改动路径与验收；批准的总计划可由一张总卡连续实施。
- 使用任务分支及工作树本地入口；不覆盖其他agent的未提交文件。
- 并行委派必须得到当前用户或适用规则授权，文件边界明确；不凭模型名称指定角色。
- 重要金融逻辑用手算和独立引擎对拍；自审和其他人员审查明确区分。
- 代码、配置、数据快照、研究结论分别版本化；保留失败和被推翻的试验。
- 数据与结果有问题时暂停相关研究，继续可以独立完成的工作。
- 不自动向主分支合并、推送、下单、购买数据或对外发消息。

提交前运行 `scripts/quant lint` 和 `scripts/quant test`。测试通过不能代替单位、
分红、现金流、历史信息可得性和许可审查。每个阶段的真实验收写入看板和审计记录。
旧任务卡及审查意见保留，重启前角色流程位于`docs/archive/pre_restart/`，不再覆盖当前授权。
