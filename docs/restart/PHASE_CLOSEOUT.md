# 投资问题、后续研究与阶段收尾条件

用户最新要求：先通过量化与回测得到清晰结论，再决定封版。
当前保持研究阶段开放，不以机器空闲、运行数量或工程测试通过代替投资问题已经回答。
“值得长期持有”与“不需要止盈、只需要找到入场点”是不同假设，分别核验。
研究对象为标普500和纳斯达克100；宽基及红利低波保留，不把标的写成不存在于本轮登记的纳斯达克1000。

## 接下来有价值的工作

1. **先收敛现有证据。** 从全部已登记5/10年窗口比较无条件分批、普通DCA、择机后持有、
   50%底仓和分批退出；报告最差/中位/最新窗口、财富差、XIRR、回本时间及等待成本，
   逐一说明低回撤是否只是现金比例高。不得只看最近五年或最佳参数。
2. **区分账户年限与真实持有年限。** 等待两年后才买入的十年账户，只持有约八年。
   下一项事件研究应从实际首次成交起再观察5/10年，未满期单列；
   与同日期普通投入比较，检查第一次入场后是否又遇下一轮熊市。
   这项新检验先冻结事件规则、窗口、成本和全部输出，再运行。
3. **补齐标普历史与可投资性。** 原FRED日线统一预热后不足完整十年账户；
   2026-10-21已取得Cboe自1975年的价格日线，按[实际入场研究协议](ENTRY_HORIZONS_PROTOCOL.md)核验，
   不能将新价格历史等同于已验收的ETF含分红投资记录。
   优先审查发行人/官方来源的长历史与公司行动、使用和留存许可；
   月度Shiller、价格指数和真实ETF分层，不能用月均价伪造每日可成交行情。
4. **明确风险管理与止盈的区别。** 先检验已登记退出规则的收益代价和下跌改善；
   若需要新测试，再单独登记固定风险配置或仓位约束。不能因为分批止盈在上涨阶段落后，
   就推导出任何仓位、任何起点都不需要风险约束。
5. **验证实际渠道与红利低波。** 在数据许可允许的范围内补齐ETF/QDII原价、NAV、折溢价、
   份额、支付日、费用税务和汇率；红利低波关注分红贡献、行业集中及与宽基组合，
   不统一要求20%恐慌，不将短历史外推15年。

免费/已有数据优先。长期PIT估值、完整历史期权链、净Gamma、未来20交易日，
有明确缺口时保留暂停；不能靠反复搜索参数制造最终样本外证据。
历史研究能回答的是已观察到的取舍和失效条件，不是未来收益承诺。

## 何时可以收尾本阶段

- 用户关心的持有/入场/退出问题得到同窗口、含负结果的清晰回答；无法验证的部分明确列出原因。
- 本轮代码、配置、来源、日期、成本、产物与复现入口一一对应；旧修订及失败保留。
- 默认资源入口与skill实际可用，精确回归通过；优化只改变执行效率。
- 形成有限候选及失效条件；没有证据的规则标为不采用或待验证，不需要强行选出冠军。
- 文档、状态、代码整合与发布清单一致，数据和未来影子运行的待办转入下一阶段。

达到这些条件可以封存“探索研究阶段”，不必把研究代码提交与全部实盘准入绑定。
但当前用户优先要求投资结论清楚，因此暂不创建阶段完成标签。

## Git交付方式

当前先保留本地可恢复提交。发布目标已配置为origin；上传时使用研究任务分支及可审查PR，
不直接覆盖v2/main，也不修改旧冻结提交。用户本轮讨论的是之后上传，并非立即推送授权。

发布前完成：

1. 把已验证性能实现、默认资源、skill及研究报告整合到同一任务分支，保留原运行的提交映射。
2. 运行全量离线测试、lint、doctor、精确真实回归；只在新改动影响行为时扩大验证。
3. 检查提交范围中的凭据、个人环境、原始行情、授权限制及大文件。仓库保存代码、摘要、
   配置和可共享清单；完整数据/账本保存在DATA_ROOT及合规备份中，不默认上传。
4. 固定最终结论、已知限制和复现说明，再检查远端状态、仓库可见性和分支差异。
5. 在用户明确要求上传后推送目标任务分支、创建PR；记录提交号、验证证据及待办。
